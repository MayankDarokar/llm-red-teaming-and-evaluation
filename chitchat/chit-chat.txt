3. DASHBOARD STATUS INCONSISTENCY ("COMPLETE" in green vs "COMPLETED" in blue)
--------------------------------------------------------------------------------
User Note:
"Also in dashboard status sometimes it writes complete in green and somethimes completed in blue this shows inconsistency it should all look the same for same status right"

Review & Explanation:
- Great eye! Here is why that happened:
  - Earlier mock data created before Mongoose schema implementation used the status string "completed".
  - The new Mongoose Evaluation model uses the normalized enum status string "complete".
  - The Dashboard badge component had a strict check `ev.status === 'complete'` for green. Because the older records had `ev.status === 'completed'`, it failed the condition and rendered in blue with default fallback styling.
- Fix Plan:
  1. Normalize status checks in the UI (e.g. `ev.status?.toLowerCase().startsWith('complete')`).
  2. Run a quick database migration/cleanup query to convert any legacy `'completed'` records to `'complete'`.

5. HOW AND WHERE ARE WE USING GEMINI, GPT, CLAUDE, AND META LLAMA?
--------------------------------------------------------------------------------
User Note:
"also show me where and how exactly are we using gemini gpt and claude and meta llama for concluding"

Review & Explanation:
- Code Location:
  - `backend/services/targetService.js` (Target LLM Service)
  - `backend/services/judgeService.js` (AI Judge Service)

- How it currently works:
  1. **When API Keys are provided in `backend/.env`**:
     - `OPENAI_API_KEY`: Routes requests to OpenAI API (e.g., `gpt-4o`, `gpt-3.5-turbo`).
     - `ANTHROPIC_API_KEY`: Routes requests to Anthropic API (`claude-3-5-sonnet`, `claude-3-haiku`).
     - `GEMINI_API_KEY`: Routes requests to Google Gemini API (`gemini-1.5-pro`).
     - `GROQ_API_KEY` / `TOGETHER_API_KEY`: Routes requests to Meta Llama models (`llama-3-70b`).

  2. **When running locally without API Keys (Free / Offline Mode)**:
     - To ensure the application works out-of-the-box without requiring users to spend money on API keys during development, `targetService.js` and `judgeService.js` include a **Smart Provider Fallback Mock**.
     - When you select `GPT-4o`, `Claude 3.5`, `Llama 3`, or `Gemini`, the mock generator simulates the specific safety guardrail behaviors of those exact models so you can test the entire pipeline end-to-end.

- To use real live models:
  Add your API keys to `backend/.env`:
  ```env

  ANTHROPIC_API_KEY=sk-ant-...
  GEMINI_API_KEY=AIzaSy...
  ```
